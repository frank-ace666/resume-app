> 测试日期：2026-10-10 · 被测版本：v1.2.0（分支 `feat/material-ui-v1.2.0`）
> 测试类型：功能性内测 + PDF 导出链路专项 + 界面视觉走查
> 测试方式：以真实构建产物（`out/`）为准，脚本驱动，非人工点击

## 一、结论摘要

| 项 | 结果 |

| 阻塞上线 | 无 |
| 主要风险 | 分页为按页高硬切，未按元素边界切分；打包流程未验证 |

## 三、测试方法

因为本应用的核心风险集中在「渲染 → 光栅化 → 落盘」这条跨进程链路上，**手工点击无法覆盖**，所以采用脚本驱动真实构建产物：

```
Electron 主进程（测试驱动）
   │  ① 通过应用自身的「打开文件」IPC 注入简历数据
   │  ② 驱动真实 UI 操作（点击导航、模板、检查、导出）
   │  ③ webContents.capturePage() 截图
   │  ④ 同时抓取 DOM 状态快照，与截图交叉核对
   ↓
out/renderer/index.html（真实构建产物，非 mock）
```

两个关键设计，都是踩坑后加的：

1. **状态快照**：每张截图同时记录 `当前分区 / 选中模板 / 预览首行 / 侧栏有无 / 页数 / 滚动宽度`。
   早期只截图不留状态，出现过「截图与预期不符但无法判断是应用问题还是测试问题」的情况。
2. **基于内容的等待**：不用固定 `sleep`，而是轮询「预览里是否已出现目标姓名」。
   固定 `sleep` 会导致拍到上一状态的残留画面（早期 1 次误判即源于此）。

PDF 校验不依赖肉眼看图，而是解析 PDF 二进制取 `/MediaBox` 与 `addImage` 的变换矩阵，得到**每页物理尺寸与图片绘制尺寸**，再与 A4（595.28 × 841.89 pt）比对。

## 五、缺陷与修复

### 🔴 B1（致命）PDF 图片尺寸溢出 3.78 倍，只导出左上角

**现象**：导出按钮提示失败；若忽略提示强行查看，导出结果只有简历左上角约 26% 的内容，且严重模糊。

**根因**：`html2pdf-browser` 内部这样放图（`dist/index.es.js`）：

```js
b = el.offsetWidth; w = el.offsetHeight
pdf.addImage(dataURL, 'JPEG', 0, 0, b, w)   // 尺寸单位跟随 jsPDF 的 unit
```

210mm 宽的元素在 CSS 里是 **793.7px**，而实测 jsPDF **没有任何一种 unit 等于 1 CSS px**：

| unit | A4 宽度 |
|---|---|
| pt | 595.28 |
| mm | 210 |
| px | **446.46** |

原实现传 `unit: 'mm'`，图片被按 794mm 画到 210mm 页面上 → 溢出 3.78 倍。

**实测证据**（修复前）：

| 用例 | 图片绘制尺寸 | A4 页面 | 结果 |
|---|---|---|---|
| 单页 | 2250.7 × 3183.3 pt | 595.28 × 841.89 | 溢出 378%，有效约 51 dpi |
| 长简历 | 2250.7 × 4688.5 pt（**1 页**） | — | 内容 5.57 页高，全塞进一页被截断 |

**修复**：不再使用该库的 `html2pdf()` 一步到位，改为保留其导出的 `html2canvas`（带中文文字重叠与 SVG `<use href>` 修复，是该库真正有价值的部分），页面尺寸与分页自行控制。`pxPerMm` 由元素布局宽度反推，因此导出结果与预览缩放级别无关。`jspdf` 提为显式依赖。

**验证**（修复后）：

| 用例 | 输出 |
|---|---|
| 单页 | 595.3 × 841.9 pt = 页面的 **100% × 100%** |
| 12 工作 + 8 项目 | **3 页**；第 1、2 页 100% × 100%，第 3 页 100% × 16.1% |
| 4 工作 + 3 项目 | 2 页；100% × 100% + 100% × 15.5% |

### 🔴 B2（致命）oklch 颜色导致 html2canvas 直接抛错

**现象**：与 B1 表现相同（导出失败），但根因完全独立 —— 即使修好 B1，导出依然失败。

**根因**：html2canvas 1.4.1 的 bundle 中 `oklch` 出现 **0 次**（不支持），而 Tailwind CSS v4 的默认调色板**全部**编译成 `oklch()`。模板里的 `text-slate-700`、`border-slate-200` 这类类名，让被捕获子树中出现了大量 oklch 值，html2canvas 解析颜色时抛错。

**实测证据**：对 `#resume-preview-content` 子树逐元素扫描计算样式 ——

| | 元素数 | oklch / color-mix 违规 |
|---|---|---|
| 修复前 | 77 | **448** |
| 修复后 | 251 | **0** |

**修复**：模板颜色改用 `shared.tsx` 的 `PRINT` 显式 sRGB 色板，并以 inline style 施加；同时禁用透明度修饰符（`text-white/90` 会编译成 `color-mix(in oklab, …)`，同样不被支持，需半透明时写 `rgba()`）。

**为什么之前没被发现**：原有的 PDF 冒烟验证使用纯 hex 内联样式，**从未覆盖到真实模板路径**。这次改为驱动真实构建产物才暴露出来。该约束已写入开发文档第九节与模板新增指引。

### 🟠 B3（严重）经典模板无技能时丢失姓名与联系方式

**现象**：简历若未填写技能，左栏（含姓名、求职意向、联系方式）整体消失，版式在填写技能前后突变。

**根因**：侧栏渲染条件写成了 `skills.length > 0`。

**修复**：侧栏改为始终渲染；技能区为空时只是该段落不出现。

**验证**：稀疏简历用例（技能 0 项）→ 状态快照 `侧栏=true`，姓名正常显示。

### 🟠 B4（严重）4 个字段「填了却永远不显示」

`Skill.category`（技能分组）、`Project.link`（项目链接）、`Education.description`（在校经历）、`WorkExperience.location`（工作地点）—— 用户可填写、可保存，但三个模板都不渲染。属于静默数据丢失。

**修复**：全部接入模板渲染；技能分组同时成为技能区的组织方式。

### 🟡 B5（中）A4 预览默认被水平裁切 241px

**现象**：默认 100% 缩放下，简历右侧内容看不见，需手动缩放或拖动滚动条。

**实测**：预览容器 `clientWidth = 553`，而 A4 渲染宽度 `794`，`hasHorizontalScroll = true`。

**修复**：默认改为「适应宽度」。

**验证**：修复后 11 个界面状态全部 `滚动宽度/容器宽度 = 553/553`，水平溢出消失。

### 🟡 B6（中）技能分类标签被硬折行

**现象**：现代 / 简约模板的技能区使用固定宽度分类列（68px / 70px），「后端与数据库」「跨端与可视化」这类 5–6 字分类放不下，被折成「后端与数据 / 库」。

**修复**：改用 `grid-template-columns: auto 1fr`，分类列按最长内容自适应，并保留 `maxWidth` 兜底防止病态长分类撑破页面。

**验证**：用行盒数量（`getClientRects().length`）判定折行 —— 6 个分类标签**全部为单行盒**，折行数 0，超出 A4 边界元素数 0。

> 测量踩坑记录：所有标签一度都报「宽 54px」，看似测量失效。实际是预览容器的 `transform: scale(0.70)` 会作用于 `getBoundingClientRect()` —— 54 / 0.70 = 78px = 6 汉字 × 13px，自洽。**量 DOM 几何时必须考虑祖先的 transform。**

### 🟢 B7–B9（低）

| 编号 | 缺陷 | 修复 |
|---|---|---|
| B7 | 状态栏版本号硬编码 `v1.0.0`，与实际版本脱节 | 由 `package.json` 经 Vite `define` 注入 |
| B8 | `resources/icon.png` 不存在，而 `build.win.icon` 指向它 → `npm run package` 会失败 | 补齐图标（程序化生成的 256×256 PNG） |
| B9 | `tsconfig.web.json` 的 `baseUrl` 已在 TS 6.0 弃用、7.0 移除 | 移除，`paths` 改为相对 tsconfig 的 `./src/*` |

## 六、被推翻的判断（测试过程中的自我纠错）

内测的价值不只是找应用的 bug，也包括纠正测试者自己的错误结论。以下三处我最初判断错误，均以实测数据为准收回：

| 初始判断 | 实测结果 | 结论 |
|---|---|---|
| 经典模板侧栏技能文字**发生重叠** | 12 行技能：重叠 0、溢出侧栏 0 | **误判**。低分辨率截图上把右侧熟练度标签看串行了 |
| 导航「简历检查」的**问题数徽标未渲染** | 状态快照为 `简历检查1` | **误判**。徽标在渲染，截图上不易辨认 |
| PDF 的修法是「把 `unit` 改成 `px`」 | `px` 单位下 A4 宽 446.46，仍溢出 1.78 倍 | **方案错误**。没有任何 unit 可行，必须自行控制定位 |

## 七、测试方法自身的问题（供后续参考）

测试脚本也出过两次故障，一度把测试问题误认为应用问题：

1. **环境变量传递失效**：测试用 preload 通过 `process.env` 读取路径，但 renderer 的 `process.env` 在窗口创建时就已固定，主进程事后修改无效 → 表现为「数据没加载 / 导出没反应」，实际是测试桩的问题。改为走 IPC 按调用时刻取值。
2. **固定 `sleep` 拍到旧帧**：`capturePage()` 可能返回滞后画面 → 表现为「截图显示的模板与设置的不一致」。改为基于内容的等待 + 状态快照交叉核对。

**教训**：涉及跨进程与异步渲染的验证，必须用**状态断言**而不是**时间等待**。
